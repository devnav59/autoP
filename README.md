# autoP — ضبط و اجرای گردش‌کار اندروید بدون مختصات

`autoP` یک برنامهٔ بومی اندروید است که با **Accessibility API** ساختار معنایی صفحهٔ برنامهٔ انتخاب‌شده را می‌خواند، کارهای کاربر را ضبط می‌کند و همان گردش‌کار را دوباره اجرا می‌کند. این پروژه برای کلیک روی نقطهٔ ثابت صفحه یا تشخیص تصویری ساخته نشده است.

## قابلیت‌ها

- انتخاب برنامهٔ هدف از میان برنامه‌های قابل اجرا
- ضبط و ذخیرهٔ محلی:
  - کلیک، لمس طولانی و انتخاب آیتم
  - دکمه‌های bottom navigation و tabهایی که رویداد Selected منتشر می‌کنند
  - ورود متن یا عدد
  - اسکرول بالا، پایین، چپ و راست و موقعیت نهایی لیست
  - مقدار نهایی SeekBar، slider و کنترل‌های دارای RangeInfo
  - کلید بازگشت
- کنترل شناور و قابل‌جابجایی از نوع `TYPE_ACCESSIBILITY_OVERLAY`، همراه دکمهٔ واضح «پایان و ذخیرهٔ ضبط»، حذف آخرین مرحله و ثبت بازگشت
- یافتن المان بر پایهٔ ترکیبی از:
  - `viewIdResourceName`
  - متن، hint و content description
  - برچسب فرزندان برای icon button و bottom navigation
  - برچسب المان‌های خواهر و والدهای معنایی
  - نوع کلاس، نقش تعاملی و RangeInfo
  - مسیر ساختاری با وزن بسیار کم و فقط برای رفع تساوی
- **بدون خواندن یا ذخیرهٔ مختصات و bounds المان‌ها**
- تطبیق سخت‌گیرانه: اگر نتیجه یکتا نباشد، اجرا متوقف می‌شود و به‌جای حدس‌زدن روی المان اشتباه کلیک نمی‌کند.
- انتظار خودکار تا ۱۵ ثانیه برای آماده‌شدن هر مرحله
- عدم ضبط فیلدهایی که اندروید به‌عنوان password معرفی می‌کند
- نگه‌داری گردش‌کارها فقط در فایل خصوصی برنامه؛ Manifest هیچ مجوز اینترنتی ندارد.
- رابط فارسی و راست‌به‌چپ
- GitHub Actions دستی برای ساخت APK و AAB ریلیز امضاشده، کنترل امضا، checksum و استخراج گواهی عمومی

## راه‌اندازی روی گوشی

1. APK را نصب کنید.
2. برنامهٔ «اتوپی» را باز کنید و «تنظیمات دسترس‌پذیری» را بزنید.
3. سرویس «موتور اجرای اتوپی» را فعال کنید.
4. یک گردش‌کار جدید بسازید، نام و برنامهٔ هدف را انتخاب و ذخیره کنید.
5. «شروع ضبط» را بزنید. در برنامهٔ هدف کارها را به‌ترتیب انجام دهید.
6. پنل ضبط را با گرفتن نوار بالای آن به محل دلخواه ببرید. در پایان دکمهٔ قرمز «پایان و ذخیرهٔ ضبط» را بزنید.
7. برای تکرار، «اجرای گردش‌کار» را بزنید.

اگر هنگام ضبط یک drag یا animation چند رویداد پشت‌سرهم فرستاده شود، برنامه آن‌ها را تا رهاشدن دست ادغام و مقدار/موقعیت نهایی را ثبت می‌کند. ورود متن نیز بعد از پایان تایپ به‌صورت یک مرحله ذخیره می‌شود.

## نکتهٔ فنی و محدودیت واقعی اندروید

هیچ برنامهٔ معمولی اندروید نمی‌تواند المان‌های **تمام** برنامه‌ها را با تضمین صددرصد و بدون همکاری برنامهٔ هدف ببیند. autoP فقط می‌تواند nodeهایی را تشخیص دهد که برنامهٔ هدف در درخت Accessibility منتشر می‌کند. در موارد زیر سیستم ممکن است اطلاعات کافی ندهد:

- بازی‌ها، Canvas/OpenGL و رابط‌های کاملاً سفارشی؛
- بعضی WebViewها یا صفحه‌هایی که accessibility آن‌ها غیرفعال شده است؛
- صفحه‌های قفل، PIN، پرداخت، مجوزهای حفاظت‌شده و برخی صفحه‌های سیستمی؛
- المان‌های بدون ID/label که چند نمونهٔ کاملاً یکسان دارند؛
- تغییر اساسی ساختار یا متن رابط برنامهٔ هدف پس از ضبط؛
- لمس یک قسمت خالی Canvas که هیچ node و هیچ رویداد `TYPE_VIEW_CLICKED` منتشر نمی‌کند.

مکان المان می‌تواند تغییر کند؛ matcher از مختصات استفاده نمی‌کند و برچسب خود المان، فرزندان، همسایه‌ها و والدها را مقایسه می‌کند. با این حال لمس کاملاً خالی صفحه هویت معنایی ندارد و Accessibility API چیزی برای ضبط آن تحویل نمی‌دهد. در این حالت پروژه عمداً از مختصات یا gesture نقطه‌ای به‌عنوان fallback استفاده نمی‌کند و به‌جای انجام عمل پرخطر متوقف می‌شود. برای بهترین نتیجه، برنامهٔ هدف باید ID پایدار، label و semantics مناسب داشته باشد. از این ابزار برای گذرواژه، کد یک‌بارمصرف، تأیید پرداخت یا دورزدن صفحه‌های امنیتی استفاده نکنید.

> انتشار در Google Play مستلزم تکمیل Accessibility API declaration، نمایش disclosure روشن و اثبات این است که قابلیت اصلی برنامه به Accessibility وابسته است. قوانین جاری Play را پیش از انتشار بررسی کنید.

## ساخت محلی

پیش‌نیازها: JDK 17 و Android SDK 35.

```bash
./gradlew :app:assembleDebug
```

خروجی debug محلی در `app/build/outputs/apk/debug/` قرار می‌گیرد. فایل GitHub Actions جداگانه‌ای برای Debug نگه‌داری نمی‌شود؛ تنها workflow پروژه، نسخهٔ Release امضاشده را تولید می‌کند.

ساخت release محلی بدون متغیرهای signing یک خروجی unsigned می‌سازد. برای signing همان چهار متغیر محیطی workflow را تنظیم کنید و سپس:

```bash
./gradlew -PVERSION_NAME=1.0.0 -PVERSION_CODE=1 :app:assembleRelease :app:bundleRelease
```

## Workflow ساخت ریلیز امضاشده

پروژه فقط یک فایل workflow قابل‌انتقال دارد. ابتدا workflowهای قدیمی Debug را حذف کنید؛ سپس فایل زیر را دستی با نام `.github/workflows/android-release.yml` منتقل کنید. فایل هم trigger از نوع `push` دارد تا روی همین شاخه فوراً شناسایی و یک Release امضاشده تولید شود، و هم `workflow_dispatch` برای اجرای دستی دارد. توجه کنید که GitHub دکمهٔ Run workflow را فقط وقتی نشان می‌دهد که فایل workflow روی شاخهٔ پیش‌فرض مخزن نیز وجود داشته باشد:

```text
workflow-files/android-release.yml
```

### ۱. ساخت keystore فقط برای بار اول

```bash
keytool -genkeypair -v \
  -keystore autop-release.jks \
  -alias autop \
  -keyalg RSA -keysize 4096 -validity 10000
```

این فایل و رمزهایش را گم نکنید؛ نسخه‌های بعدی یک اپ باید با همان کلید امضا شوند. فایل `jks` یا کلید خصوصی را داخل Git commit نکنید.

### ۲. تعریف GitHub Actions secrets

برای یک نصب آزمایشی، workflow در نبود Secret یک گواهی موقت می‌سازد و build را متوقف نمی‌کند؛ اما APK حاصل نمی‌تواند نسخه‌ای را که با اجرای قبلی و کلید دیگری نصب شده به‌روزرسانی کند. برای انتشار واقعی و آپدیت‌پذیری، در مخزن GitHub به **Settings → Secrets and variables → Actions** بروید و هر چهار Repository secret زیر را بسازید:

| Secret | مقدار |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | محتوای base64 فایل keystore |
| `ANDROID_KEYSTORE_PASSWORD` | رمز keystore |
| `ANDROID_KEY_ALIAS` | alias، مثلاً `autop` |
| `ANDROID_KEY_PASSWORD` | رمز کلید |

Linux:

```bash
base64 -w 0 autop-release.jks
```

macOS:

```bash
base64 < autop-release.jks | tr -d '\n'
```

### ۳. اجرای دستی

از تب **Actions**، workflow «Build signed Android release» را انتخاب کنید و **Run workflow** را بزنید. `version_name` و `version_code` را وارد کنید. بعد از موفق‌شدن build، در بالای همان صفحهٔ اجرای Action و داخل **Job summary** دکمهٔ «دانلود APK و AAB امضاشده» نمایش داده می‌شود. Artifact به‌مدت ۳۰ روز قابل دانلود است و شامل موارد زیر است:

- APK امضاشده برای نصب مستقیم؛
- AAB امضاشده برای انتشار؛
- `signing-certificate.pem`، یعنی گواهی/کلید عمومی قابل انتشار؛
- fingerprintهای امضا و `SHA256SUMS.txt`.

اگر گزینهٔ `create_github_release` را فعال کنید، لینک صفحهٔ Release نیز در همان summary نشان داده می‌شود و فایل‌ها از صفحهٔ Releases به‌صورت مستقیم قابل دانلود خواهند بود.

امضای APK با **کلید خصوصی** انجام می‌شود و گواهی عمومی داخل APK قرار می‌گیرد. چیزی به نام امضای امن با «کلید عمومی» وجود ندارد؛ workflow کلید خصوصی را فقط از GitHub Secrets می‌گیرد و فقط گواهی عمومی را در artifact منتشر می‌کند.

## ساختار پروژه

- `accessibility/AutomationAccessibilityService.kt`: ضبط، کنترل شناور و موتور اجرای مرحله‌ای
- `accessibility/SelectorFactory.kt`: تولید fingerprint معنایی بدون bounds
- `accessibility/NodeMatcher.kt`: امتیازدهی و الزام یکتابودن node
- `data/`: مدل JSON و ذخیره‌سازی اتمیک محلی
- `ui/`: فهرست گردش‌کار، ویرایش مراحل و انتخاب برنامه

## حریم خصوصی

این برنامه backend، analytics و مجوز اینترنت ندارد. متن ورودی‌های عادی جزئی از گردش‌کار و در فایل خصوصی `workflows.json` ذخیره می‌شود؛ بنابراین برای اطلاعات حساس از آن استفاده نکنید. فیلدهایی که برنامهٔ هدف درست به‌عنوان password علامت‌گذاری کرده باشد ضبط نمی‌شوند.
